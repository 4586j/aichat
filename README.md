# 栖忆 · MEMORY STUDIO

栖忆是一个面向本地、单用户使用的 AI 对话与记忆空间。它把角色聊天、个人知识库、长期记忆和定时任务放在同一个中文界面中，使用 Node.js 提供本地服务，使用 SQLite 保存数据。

## 项目功能

- **角色对话**：创建和切换不同角色，保留多段会话；回答可结合相关知识片段与角色记忆，并展示引用来源和召回的记忆。
- **对话状态**：用户情绪、精力和当前需要与 AI 角色的表达状态、主动程度分开展示；熟悉程度以阶段显示。详情中可查看原话依据、判断把握、有效期与熟悉分数，并手动调整或恢复自动判断。
- **人设工坊**：编辑角色名称、简介、语气、开场白与系统提示词；从聊天记录中分析指定人物的表达风格，生成可编辑的人设草稿，确认后再创建角色。
- **本地知识库**：导入 TXT、Markdown、JSON、文字型 PDF 和 DOCX，在本地提取文字、分块并进行关键词检索。知识库由全部角色共享；单个文件最大 8 MiB，提取后的文字最多 30 万字符。文本文件需使用 UTF-8 编码，扫描型 PDF 需先自行进行 OCR。
- **长期记忆**：按角色保存事实、偏好、目标、约束与摘要；支持手动记录、从对话总结、按消息数或时间自动总结，以及编辑、固定、归档、恢复和删除。记忆会根据重要性、置信度、访问情况与时间衰减评分，维护时将符合条件的弱记忆归档。
- **记忆图谱**：手动填写或通过模型提取实体与关系，用交互图谱查看记忆、关系和原文证据，支持搜索、筛选与关联召回。
- **定时任务**：支持应用内提醒、角色上下文总结和 AI 提问，可设置一次性执行或按分钟固定间隔重复，并查看执行状态与结果。
- **模型设置**：连接支持 OpenAI 兼容聊天接口的远程或本机模型服务，配置 Base URL、模型名称与 API Key，并手动测试连接。
- **表情包回复**：内置 6 张原创小叶贴纸，支持上传、编辑标签、启用和停用本地表情；AI 优先本地选图，没有合适素材时可使用已配置的联网检索服务。
- **歌曲推荐与背景音乐**：连接你现有的音乐平台，优先查本地曲库，再搜索 QQ／网易云。聊天中显示歌曲卡片，常驻播放器支持队列、音量、循环和进度调整，切换页面时继续播放。
- **发送邮件**：配置 SMTP 后编写纯文本邮件，支持抄送、密送、AI 起草及将 AI 回复带入草稿；预览并明确确认后发送，保留可删除的本地发送记录。
- **配置指南与 AI 帮助**：内置六份离线配置文档；在聊天中询问配置问题时，检索相关原文交给模型并展示依据。可手动从 GitHub 更新文档副本，也提供外部 AI 可读的 `llms.txt` 索引。
- **宠物陪伴**：四款原创生成的 Q 版形象，支持切换、取名、摸摸、点心和玩耍；宠物随聊天等待、回复和音乐播放呈现轻动效，可静止或隐藏，偏好和互动记录保存在本地。

## 本地启动

### 环境要求

- Node.js **22.18.0 或更高版本**（见 `package.json` 中的 `engines`），并安装 npm。
- 支持 JavaScript 的现代浏览器。
- 使用 AI 功能时，需要可访问的 OpenAI 兼容模型服务；服务商要求认证时，还需准备 API Key。

项目使用 Node.js 内置的 SQLite，无需单独安装数据库，也无需构建前端。未配置模型时仍可启动界面、管理角色、导入和检索文档、手动管理记忆，以及使用应用内提醒。

### 安装并运行

```sh
git clone git@github.com:4586j/aichat.git
cd aichat
npm ci
npm start
```

如果已经在项目目录中，直接执行 `npm ci` 和 `npm start` 即可。

看到终端输出“栖忆 AI Agent 已启动”后，在浏览器打开：

[http://127.0.0.1:4317](http://127.0.0.1:4317)

开发时可使用自动重启模式：

```sh
npm run dev
```

运行期间保持终端中的服务进程开启，按 `Ctrl+C` 停止服务。

### 首次配置模型

1. 打开左侧“设置”，填写服务商提供的 **Base URL** 和 **模型名称**。
2. Base URL 填写接口基础地址，例如项目默认的 `https://api.openai.com/v1`。程序会自动追加 `/chat/completions`，不要把完整聊天接口地址填入此处。
3. 按服务要求填写 API Key；无需认证的本机兼容服务可留空。
4. 点击“保存设置”，再点击“测试已保存的连接”。测试会向模型发送一条实际请求。
5. 连接成功后，在“对话”中选择角色并开始聊天，也可先到“知识库”导入参考资料。

也可以先在聊天中输入第一句话。模型尚未配置时，点击发送会显示“本地配置助手”的快捷配置消息和三步方法，输入内容继续保留，不调用模型或创建空会话。点击“快捷配置模型”填写并保存后，可手动测试，再“继续发送”；重复点击不会叠加引导。此引导只在当前页面显示，不写入 AI 聊天历史或记忆；未发送的草稿刷新后不会保留。

Base URL、模型名称和记忆设置会保存到本地数据库。界面输入的 API Key 仅保留在当前服务进程内，不写入数据库；重启服务后需重新输入，或通过 `AI_API_KEY` 环境变量提供。人物分析、记忆总结和图谱提取需要模型能够按提示返回有效的 JSON 内容。

### 可选环境变量

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `4317` | 本地服务端口，范围为 `1`～`65535`。 |
| `AGENT_DATA_DIR` | 项目目录下的 `data/` | 数据目录，程序会在其中创建 `agent.sqlite`；自定义相对路径按启动命令所在目录解析。 |
| `AI_API_KEY` | 空 | 服务启动时读取的模型 API Key；Base URL 和模型名称仍需在界面中配置。 |
| `SMTP_PASSWORD` | 空 | 服务启动时读取的 SMTP 密码或邮箱授权码；主机、用户名及发件邮箱在界面中保存。 |

例如，在 Windows PowerShell 中更改端口后启动：

```powershell
$env:PORT = "4417"
npm start
```

此时访问 [http://127.0.0.1:4417](http://127.0.0.1:4417)。

`npm start` 和 `npm run dev` **不会自动读取 `.env`**。如需使用配置文件，可自行在项目根目录创建 `.env`，按需填写：

```dotenv
PORT=4317
AGENT_DATA_DIR=./data
AI_API_KEY=替换为你的密钥
```

然后显式加载该文件启动：

```sh
node --env-file=.env server.mjs
```

该方式使用 [Node.js 的 `--env-file` 选项](https://nodejs.org/docs/latest-v22.x/api/cli.html#--env-filefile)。`.env` 已被 Git 忽略；无需认证的模型可省略 `AI_API_KEY`。

## 表情包与音乐配置

进入“设置”，在“让对话多一点表达”区域配置，然后点击“保存媒体设置”。这些设置与模型设置分别保存，不会自动测试连接。

### 本地与联网表情包

默认内置贴纸可直接供 AI 选择；模型按语境决定是否附图，每次最多一张，不要求每轮都发送。在本地图库可上传 PNG、JPEG、GIF 或 WebP，填写名称、使用场景和标签。上传图片不需要视觉模型，图片内容不自动上传给聊天模型，选图依据是你填写的文字说明。

每张文件最多 4 MiB，宽高不超过 4096 像素；最多 100 张上传图片，合计 64 MiB。重复图片按内容去重，图片与元数据保存在本地 SQLite，随数据目录一起备份。停用只阻止再次选中；永久删除会使历史附件无法再加载图片，但保留原来的说明。动图需要点击后才加载和播放。

联网补充使用**自定义、获准使用的表情检索服务**，服务地址默认留空。不内置 Tenor、GIPHY 或 KLIPY 的代理适配器。自行接入这些供应商时，应先核对其客户端访问、缓存和展示要求，不能直接将它们的原始接口地址填入本设置。

检索服务须接受 `GET <服务地址>?q=<简短检索词>&limit=1`，返回：

```json
{
  "stickers": [
    {
      "url": "https://images.example.com/celebrate.gif",
      "alt": "开心庆祝",
      "animated": true
    }
  ]
}
```

没有结果时返回 `{"stickers": []}`。只在本地没有匹配且开启联网补充时调用；请求仅携带检索词，不发送整段会话。若配置表情服务 API Key，检索请求使用 `Authorization: Bearer <key>`。

默认只允许图片 URL 与检索服务同源。使用独立 CDN 时，需要在“额外允许的图片来源”中填写完整来源，例如 `https://images.example.com`。图片通过固定资源接口读取，限制大小和真实图片类型，不接受远程 SVG、任意 HTML 或未允许的来源，也不将密钥附加到图片请求中。在线图片文件不保存到本地，历史附件保存图片引用；配置的来源应允许这种使用方式。检索失败不会阻止文字回复。

### 你的音乐平台

**音乐服务地址默认留空**，未配置时不连接本机端口或其他备用服务，也不搜索或读取曲库。AI 仍可提出歌曲推荐，但卡片会明确提示需配置后查询，不显示虚假的可播放状态。

准备好音乐服务后，在设置中填写基础地址；开启鉴权时填写音乐服务 API Key。保存后可点击“测试已保存的音乐连接”。适配器复用现有 Flask 音乐平台的接口：

| 音乐平台接口 | 用途 |
| --- | --- |
| `GET /api/status` | 测试服务与来源状态。 |
| `GET /api/library` | 读取已有的本地曲库。 |
| `GET /api/search?keyword=...&source=qq或netease` | 本地无匹配时补充在线歌曲。 |
| `GET /api/local_play?name=...` | 播放本地歌曲。 |
| `GET /api/stream?songmid=...&source=...&quality=320` | 在线歌曲播放。 |
| `GET /api/local_cover?name=...` | 本地歌曲封面资源接口。 |

Node.js 在服务端通过 `X-API-Key` 转发鉴权，浏览器使用同域播放路径。实际播放时请求音频流并转发 Range，歌曲记录保存来源与稳定标识；修改音乐服务地址后，旧卡片需要重新搜索，以免将旧标识发送到另一个服务。

点击右上角音符按钮可以搜索、浏览本地曲库、建立当前播放队列并调整播放音量和循环方式。歌曲卡片支持“播放这首歌”和“设为背景音乐”。播放推荐歌曲时暂停原背景音乐，结束后恢复；用户手动暂停、关闭或切歌时取消该恢复操作。播放器不随页面重新绘制，切换六个页面不会重建音频元素。音量和循环偏好可保留，刷新页面后不会自动出声；手机锁屏或浏览器被系统挂起后的连续播放不作保证。

两种媒体服务的 API Key 只在服务进程内保留，重启后需重新填写，或在启动前设置 `MUSIC_API_KEY`、`STICKER_API_KEY` 环境变量。服务地址和普通设置持久化保存。第三方账号 Cookie 继续由你的音乐平台管理，本项目不导入 Cookie。

## 邮件配置与发送

1. 在“设置”底部的“把想说的话，寄出去”区域填写 SMTP 主机、端口、加密方式、用户名和发件邮箱。主机填写纯域名或 IP，例如 `smtp.example.com`，不带 `https://`。未配置时可以先写草稿，不能提交邮件。
2. 按邮箱服务商说明填写 SMTP 密码或授权码。支持 TLS（常用端口 465）和强制 STARTTLS（常用端口 587），校验证书，不支持明文连接。端口以实际服务商配置为准。
3. 点击“保存邮件设置”，然后手动点击“测试已保存的 SMTP 连接”。保存本身不会连接邮箱；测试只检查连接与认证，不发送邮件，也不能确认该发件邮箱已获准投递。
4. 点击顶部信封按钮开始写信。填写纯邮箱地址，多个地址用逗号分隔；支持抄送与密送，每封合计最多 20 个不同地址，主题最多 200 字符，正文最多 50000 字符。当前支持纯文本，不含附件或 HTML。
5. 点击“预览邮件”，核对发件人、全部收件地址、主题与正文，再点击“确认发送”。预览有效期 10 分钟；返回修改内容、修改 SMTP 配置或重启服务后需要重新预览。重复确认同一份预览不会重复发信。

“让 AI 帮我起草”会把你填写的起草需求发送给当前配置的模型，只生成可编辑的主题和正文；不会附带 SMTP 配置和收件地址。聊天中的“写成邮件”会把该条 AI 回复复制为正文。AI 起草需要模型配置；手动写信与发送不依赖模型。草稿只在当前页面内存中保留，刷新页面后丢失；发送预览与发送记录保存在本地数据库。

主机、端口、用户名、发件邮箱和普通设置会持久化。密码只保留在服务进程内，保存成功后输入框清空，留空保留已有密码，也可主动清除。更换主机或用户名时需要重新填写密码。重启服务后重新输入，或事先设置 `SMTP_PASSWORD` 环境变量。使用环境变量时，先保存普通配置，再重启服务加载密码。

“查看发送记录”显示最近 100 次发送尝试，含正文、收件人、接受／拒绝名单和状态，可逐条删除本地记录。**“服务器已接受”表示 SMTP 提交成功，最终送达仍需关注退信**；部分地址被拒绝时会分别列出。若发送中途断线或服务中断，结果可能标为“待核实”，请先检查邮箱或向收件人核实，避免重复发送。系统不会自动重试，AI 与定时任务不会自动发信。删除本地记录不能撤回已提交的邮件。

首次配置环境变量可复制 [.env.example](.env.example) 到本机 `.env`；仍需用 `node --env-file=.env server.mjs` 显式加载。文档维护、生成与发布步骤见[配置文档维护说明](docs/configuration/README.md)。

## 宠物陪伴

点击顶部宠物头像／爪印进入“宠物小窝”。默认由奶油猫“团团”陪伴，也可选择柴犬“豆包”、垂耳兔“糯米”或小狐狸“栗栗”，每位都有独立的名字和互动记录。点击形象或“摸摸”加 1 陪伴点数，“喂点心”加 2 点，“玩一会儿”加 1 点；同一宠物每秒最多记录一次，暂时离开不会扣分。

桌面聊天侧栏显示陪伴卡片，手机使用紧凑条，不悬浮遮挡输入框和音乐播放器。聊天等待、回复完成以及实际音乐播放时呈现轻动效；在小窝中关闭动效可安静陪伴，系统的减少动态效果也会生效。关闭显示后保留爪印入口。宠物图片随项目分发，离线可用，不需要配置新的 Key 或模型。名字、所选形象、显示与动效偏好、点数及互动计数保存在 SQLite；不会自动上传宠物资料或写入 AI 记忆。

形象说明与素材文件见[宠物素材记录](docs/pet-assets.md)。当前为整体呼吸、摆动、跳跃等 CSS 动效。

## 本地数据与使用范围

- 默认数据库为 `data/agent.sqlite`，保存角色、会话、提取后的文档文字、记忆、图谱、设置、任务、媒体素材和邮件记录。导入文档的原文件不保留，需自行保存原件。
- 备份前先正常停止服务，再复制整个数据目录；`data/` 已被 Git 忽略。本地数据库未加密。
- 服务仅监听 `127.0.0.1`，面向单用户本机使用。聊天、人物分析、记忆总结、图谱提取、邮件起草及 AI 任务会将相关文本发送至配置的模型；聊天请求还可能包含相关知识片段和长期记忆。确认邮件后，收件地址和邮件内容会发送至配置的 SMTP 服务。
- 定时任务仅在服务运行时执行。关闭服务或电脑休眠时暂停；应用内提醒的结果在应用中查看。

## 对话状态与熟悉程度

聊天工具栏下方有两行状态：“你”展示当前情绪、精力和交流需要，“角色”展示表达状态与主动程度，右侧只显示“初识／逐渐熟悉／熟悉”阶段。点击整条状态栏打开“此刻的对话状态”。

| 项目 | 可显示或指定的内容 |
| --- | --- |
| 用户情绪 | 暂不判断，或最多两种情绪：平静、开心、有些烦躁、失落、担心、兴奋；情绪强度 1～5 在详情查看。 |
| 用户精力 | 未知、充足、一般、疲惫。 |
| 用户当前需要 | 尚不明确、想被倾听、想要建议、一起解决问题、轻松聊聊。 |
| AI 角色表达状态 | 跟随人设、认真、温和关切、轻松、好奇、俏皮。 |
| AI 主动程度 | 少追问、正常、主动一点。 |
| 熟悉程度 | 初识（0～24）、逐渐熟悉（25～59）、熟悉（60～100）；具体分数和计算依据在详情查看。 |

前五项为当前会话的短期状态，每项最多有效 30 分钟，不传给其他会话。自动判断复用每次聊天的模型请求：模型在回复末尾附带状态元数据，应用校验用户原话、选项与强度后单独保存，聊天正文不显示协议标记。每项“查看判断依据”可展开引用的用户原话、消息编号、判断把握及更新时间。模型没有返回可用依据时保留有效状态或默认值；把握低时显示未知／默认值，疲惫不会直接等同悲伤。

在详情勾选某项“由我指定”后选择状态，可填写本地备注。手动项在有效期内优先，不会被自动判断覆盖；取消勾选并保存后，该项下次发言可恢复自动判断。可切换“AI 辅助判断”“只使用我指定的状态”或“关闭状态辅助并清空临时状态”，也可仅清空当前会话的状态。修改用于后续回复，不会改写历史消息。尚未聊天时保存短期状态会明确创建该角色的会话并保留当前草稿；只调整熟悉程度不会创建空会话。

熟悉程度按角色计算，不由模型直接打分。仅计入置信度至少 0.7、活跃且不重复的非摘要记忆：你手动添加的记忆，或你在记忆编辑器中确认保存过正文的提取记忆。每条 8 分、每类资料 3 分，有重复提及的记忆每条另加 2 分（最多 10 条），上限 100。自动提取但尚未确认的记忆、摘要、归档资料不计入；删除或归档已确认资料会重新计算，暂时不聊天不扣分。可勾选“手动设定熟悉程度”填写 0～100 分及依据，取消后恢复自动计算。手动熟悉分数按角色持久保存，不受短期状态的 30 分钟有效期影响。

这些状态用于调整措辞、长度和追问节奏；疲惫或想被倾听时，宠物也会暂时静止陪伴，原有动效偏好不变。状态不代表心理诊断，熟悉程度表示已确认的资料量，不等同信任、好感或操作权限。状态备注仅在本地展示，不随状态字段发送给模型；自动状态引用的原话仍属于正常聊天历史。状态字段本身不写为长期记忆。协议、存储和并发处理见 [对话状态实现说明](docs/chat-state.md)。

## 测试

运行服务、存储、知识库、记忆、图谱、对话状态、媒体、邮件、配置指南、模型配置与调度相关测试：

```sh
npm test
```

运行浏览器界面测试：

```sh
npm run test:ui
```

界面测试默认使用本机已安装的 Google Chrome，也可通过 `PLAYWRIGHT_CHANNEL` 环境变量选择其他已安装的兼容浏览器通道，例如 `msedge`（参见 [Playwright 浏览器通道文档](https://playwright.dev/docs/browsers#google-chrome--microsoft-edge)）。测试会自动启动 `http://127.0.0.1:4318` 的独立服务，使用内存数据库与模拟模型回复，无需真实 API Key。运行前请确保该端口未被其他服务占用。HTTP 相关测试需要允许本机回环网络连接。

邮件测试使用模拟传输和本机回环 SMTP 服务，验证预览确认、防重复发送、失败状态和密送邮件头，不连接外部邮箱、不发送真实邮件。界面测试的邮件服务也完全离线。

配置指南测试会验证生成的文档包及 `llms.txt` 与 Markdown 一致。修改指南后先运行 `npm run docs:build`，也可单独运行 `npm run docs:check`。GitHub 更新与模型回答均使用模拟服务测试，不发出真实文档更新请求。
