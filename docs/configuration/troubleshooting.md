# 常见问题与排查

适用于栖忆 1.0.0。可以向 AI 描述现象、发生步骤和经过遮盖的错误类型。真实 API Key、密码、授权码、Cookie 不要发送到聊天或公开仓库。AI 看到的是文档和有限的字段填写状态，不会据此假装实际测试过服务。

## 重启后 Key 或密码“不见了”

模型 API Key、音乐 Key、表情 Key 和 SMTP 密码只保留在服务进程内。输入框在保存后清空是正常现象，状态提示说明服务端是否有值。重启后需在设置中重新填写，或通过环境变量提供。只创建 `.env` 但执行 `npm start` 不会加载文件；请用 `node --env-file=.env server.mjs`。更换 SMTP 主机或用户名也会清除旧密码。

## 模型连接失败

确认先“保存设置”再“测试已保存的连接”，检查 Base URL 是否错误包含 `/chat/completions`、模型 ID 是否真实可用、Key 是否属于同一服务。401/403 通常与认证或权限有关，404 检查路径和模型，429 检查限流与额度。超时检查服务启动情况和网络。未配置模型时仍能直接阅读配置指南，但 AI 无法在线回答配置问题。

## AI 没有发送表情包

表情不是每轮必发。检查允许 AI 配图、本地图片启用状态，以及名称、场景和标签是否能表达当前语境。最近两条回复用过的图片会暂时排除。联网地址为空时仅用本地；联网需要兼容本项目的检索协议，普通网页和任意图片网址不适用。图源跨域时检查允许来源；动图需要点击加载，已删除的上传图在旧记录中无法恢复。

## 没有音乐、连接失败或没有声音

音乐地址为空时“音乐服务未配置”是预期状态。填写后先保存，再手动测试。确认源音乐平台在运行，基础地址能从 Node.js 服务所在机器访问，Key 和第三方登录状态有效。先尝试本地曲库，再检查在线来源；在线搜索成功不等于实际可播放。播放需要点击，检查播放器是否暂停、音量是否为零、浏览器或系统是否静音、音源编码是否可解码。修改服务地址后重新搜索旧歌曲。

## 邮件失败、部分接受或收不到

确认 SMTP 主机不含协议与路径，端口和加密方式匹配，服务商允许 SMTP，使用其要求的密码或独立授权码。用户名、发件地址与账号权限应匹配。测试成功只表示连接和认证成功。发送记录“部分接受”需核对已接受与已拒绝名单；不要向已接受的地址盲目重发。“服务器已接受”后收不到，可检查退信、垃圾邮件及服务商投递记录。显示“结果待核实”时先核实发件或收件情况，再决定是否重新发送。

## 宠物图片或动效没有显示

先从顶部爪印入口进入小窝，确认“在聊天中显示宠物”已开启。关闭“开启轻动效”或系统开启“减少动态效果”时，形象会静止，这是预期行为。宠物形象为项目 `public/assets/pets/` 中的本地 PNG 文件，缺失时需恢复对应资源，和模型 Key 或外部图源无关；图片暂时失败时会显示替代提示。手机键盘弹出时紧凑陪伴条会临时收起。互动过快时会提示刚刚收到，不会重复加分；稍等一秒再试即可。

## GitHub 指南更新失败

内置指南可以离线阅读，不依赖 GitHub。更新按钮只读取固定仓库 `4586j/aichat` 的文档包，不会上传设置、问题或密钥。仓库未公开、文档包尚未推送、网络不通或 GitHub 限流均可能导致更新失败，此时继续使用已验证的缓存或内置副本。文档包必须匹配本应用版本和格式；不会加载任意用户提供的网址。
