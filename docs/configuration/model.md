# 模型连接与 API Key

适用于栖忆 1.0.0。支持提供 OpenAI 兼容聊天接口的远程或本机服务。本项目调用聊天完成接口，不要求模型具有网页浏览或工具调用能力。

## 准备什么

从自己的服务商后台或本地模型服务获取三个值：接口基础地址、可用的模型 ID、API Key。每家服务商的模型名称、鉴权和额度不同；本项目文档不提供通用的真实 Key，也不保证某个第三方服务或模型可用。

## 在哪里填写

还没配置模型时，也可以先在聊天中写第一句话并点击发送。应用会显示本地快捷配置消息，保留这句话，提供“快捷配置模型”“查看配置方法”入口。快捷窗口只保存模型连接信息，不会自动测试或把第一句话发送给服务商。保存后可点击“测试已保存的连接”，再“继续发送”。引导不依赖模型或 GitHub，重复发送不会刷出多张配置卡片。

进入“设置 → 模型连接”。在 Base URL 中填写服务商指定的基础地址，例如占位示例 `https://api.example.com/v1`；模型名称填写该服务实际提供的模型 ID；API Key 填写对应服务的密钥，本机服务不要求认证时可留空。先点击“保存设置”，再点击“测试已保存的连接”。测试会向保存的模型服务发送一条真实请求。

## Base URL 的常见错误

程序会在 Base URL 后自动追加 `/chat/completions`。不要把完整的 `/chat/completions` 接口填入基础地址，否则会重复拼接。地址必须为 http 或 https，不含用户名、密码、查询参数或片段。是否需要 `/v1` 以服务商文档为准，不能给所有服务强行追加同一个前缀。示例域名不是可用的模型服务。

本机模型服务的地址必须能从运行 Node.js 的机器访问。`127.0.0.1` 指向应用服务进程所在机器；服务在容器或其他机器上运行时，需要使用对应的可达地址。

## API Key 的保存规则

Base URL、模型名称和记忆设置持久化。API Key 只保留在当前服务进程内存中。输入框留空表示保留当前密钥；勾选“清除当前运行期密钥”后保存才会清除。重启后重新填写，或在启动前设置 `AI_API_KEY`。不要把密钥贴进聊天让 AI 帮忙检查，请在密码输入框中填写。

## 连接失败时如何排查

- 401 或 403：检查 Key 是否属于当前服务、是否过期及是否有模型权限。
- 404：检查基础地址、是否重复填写接口后缀、模型 ID 是否准确。
- 429：检查服务额度和限流，稍后重试。
- 无法连接或超时：检查服务是否启动、地址与网络是否可达。
- 返回内容格式无效：服务需要返回兼容的聊天响应；人物分析、记忆总结、图谱提取、邮件 AI 起草还需要模型按提示输出 JSON。

保存配置、界面显示“已填写”与连接成功是不同状态。没有执行连接测试时，AI 只能指出字段是否缺失，不能宣称服务已经可用。
