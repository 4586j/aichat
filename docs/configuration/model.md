# 模型连接与 API Key

适用于栖忆 1.0.0。支持提供 OpenAI 兼容聊天接口的远程或本机服务。本项目调用聊天完成接口，不要求模型具有网页浏览或工具调用能力。

## 准备什么

从自己的服务商后台或本地模型服务获取三个值：接口基础地址、可用的模型 ID、API Key。每家服务商的模型名称、鉴权和额度不同；本项目文档不提供通用的真实 Key，也不保证某个第三方服务或模型可用。

## 在哪里填写

还没配置模型时，也可以先在聊天中写第一句话并点击发送。应用会显示本地快捷配置消息，保留这句话，提供“快捷配置模型”“查看配置方法”入口。快捷窗口只保存模型连接信息，不会自动测试或把第一句话发送给服务商。保存后可点击“测试已保存的连接”，再“继续发送”。引导不依赖模型或 GitHub，重复发送不会刷出多张配置卡片。

进入“设置 → 模型连接”。在 Base URL 中填写服务商指定的基础地址，例如占位示例 `https://api.example.com/v1`；模型名称填写该服务实际提供的模型 ID；API Key 填写对应服务的密钥，本机服务不要求认证时可留空。在模型连接区点击“保存模型配置”，再点击“测试已保存的连接”；有未保存的模型修改时，也可直接点击“保存并测试连接”，程序先保存本轮模型字段，再发送一次测试。模型区操作不保存尚未提交的记忆设置，页面下方“保存设置”仍可一次保存两类字段。测试会向保存的模型服务发送一条真实请求。

## Base URL 的常见错误

程序会在 Base URL 后自动追加 `/chat/completions`。不要把完整的 `/chat/completions` 接口填入基础地址，否则会重复拼接。地址必须为 http 或 https，不含用户名、密码、查询参数或片段。是否需要 `/v1` 以服务商文档为准，不能给所有服务强行追加同一个前缀。示例域名不是可用的模型服务。

本机模型服务的地址必须能从运行 Node.js 的机器访问。`127.0.0.1` 指向应用服务进程所在机器；服务在容器或其他机器上运行时，需要使用对应的可达地址。

## API Key 的保存规则

Base URL、模型名称和记忆设置持久化。界面填写的模型 API Key 保存到本机数据目录的 `model-key.local`，重启后自动恢复，不写入数据库、浏览器或 Git。Windows 使用当前用户的系统加密；其他系统使用仅文件所有者可读写的本地文件。输入框留空表示保留当前密钥；勾选“清除本机模型密钥”并保存后会持续清除，即使 `.env` 中设置了 `AI_API_KEY` 也不会重新启用；若要使用新 Key，请取消勾选并填写。尚未通过界面保存或清除时，启动可从本机 `.env` 或进程环境变量读取 `AI_API_KEY`，界面不会改写 `.env`。不要把密钥贴进聊天，请在密码输入框中填写。

保存失败时不会继续测试旧配置；保存过程中又修改了模型字段时，也会保留新草稿并提示再次保存。填写本身不发送测试请求。

## 连接失败时如何排查

- 401 或 403：检查 Key 是否属于当前服务、是否过期及是否有模型权限。
- 404：检查基础地址、是否重复填写接口后缀、模型 ID 是否准确。
- 429：检查服务额度和限流，稍后重试。
- 无法连接或超时：检查服务是否启动、地址与网络是否可达。
- 返回内容格式无效：服务需要返回兼容的聊天响应；人物分析、记忆总结、图谱提取、邮件 AI 起草还需要模型按提示输出 JSON。

保存配置、界面显示“已填写”与连接成功是不同状态。没有执行连接测试时，AI 只能指出字段是否缺失，不能宣称服务已经可用。

## 聊天理解模式

“设置 → 模型连接 → 聊天理解模式”默认使用兼容模式，也可选择试用语义模式。语义模式先用模型分析本轮意图、检索需要的资料与媒体，再流式生成回答；一般每轮发送两次模型请求，响应时间和费用可能增加。分析阶段最多等待 75 秒，输出预算为 3200 tokens；支持推理的模型可能将其中一部分用于内部推理，可随时点击“停止生成”。对火山方舟官方地址上的 `ark-code-latest`，程序在意图分析及语义模式最终回答中关闭深度思考，以减少输出预算耗尽和超时；这也意味着这些回答不使用该模型的深度思考能力。意图分析使用已验证的结构化输出或原生工具参数，其他服务不会收到这些专有参数。分析失败时不会根据旧的关键词规则猜测媒体动作。可随时切回兼容模式。

“点歌调用方式”在语义模式下选择意图分析的协议：文本标签使用 JSON，原生工具调用需要模型支持 tools。音乐卡片仍须点击才播放，聊天不会直接控制播放队列。语义模式的实际理解效果取决于所选模型，请先在测试会话中验证。

在已验证的火山方舟 `ark-code-latest` 上，语义回答使用结构化段落、来源编号和本轮表情候选；状态预测直接使用结构化对象；段落完成校验后逐段显示。服务返回不符合结构的内容时，本轮可能失败，不会自动重试收费请求。其他服务使用兼容的回答格式。来源编号只能确认引用属于本轮资料，不能保证资料必然支持对应结论。

## 流式与模型提供的思考内容

聊天请求会发送 stream=true，逐步读取 SSE 的正文与 reasoning_content／reasoning 字段。兼容模式无需额外开启第二次模型分析；语义模式先进行一次意图分析。两者都不要求服务暴露它没有提供的思考内容。支持的服务会边生成边显示；仍返回 application/json 的服务兼容原有正文。未知流式字段忽略，数据过大、错误或提前断开会中止，不自动重复发送收费请求。连接测试、分析和后台总结仍使用原有非流式方式。
