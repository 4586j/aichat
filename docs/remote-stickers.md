# 远程表情图库 v1 接入

本实现适配 2026-10-29 提供的 `api-contract.md` 与 `chat-integration.md`。图库服务需要自行部署；本项目没有内置公网地址或 Key。管理端登录、上传、审核与密钥签发由图库后端负责。

## 配置

1. 在“设置 → 让对话多一点表达”填写稳定的完整检索地址 `https://<图库域名>/api/v1/stickers/search`，不附加查询参数。保持表情总开关和联网补充开启。
2. 在密码框填写同时具有 `catalog:read` 和 `images:read` 的专用 Key，或在启动前设置 `STICKER_API_KEY`。保存时留空保留，清除必须显式勾选；页面只显示是否已配置，Key 不写入 SQLite。
3. 新图库图片必须与检索接口同源，并使用 `/api/v1/images/<64位小写哈希>`。`stk_<哈希>` 必须与图片路径一致，不允许查询签名、任意外链或跳转。“额外允许的图片来源”仅用于已有远程历史图。

生产配置切换不属于代码适配过程。切换前先只读核验当前完整服务地址和已有远程引用；保留原地址与路径，或者另行设计来源映射／迁移。更换完整地址会使旧引用失效。此次测试只用内存库和临时测试库，未读取生产聊天或秘密配置，也未替换实际服务设置。

## 语义查询与候选

`lib/sticker-gallery.mjs` 集中处理图库枚举、查询生成及字段验证。内部联动场景显式转换为图库场景：

| 联动场景或表达意图 | 图库 scene | 图片表达 emotion |
| --- | --- | --- |
| 温和陪伴／抱抱安慰 | `comfort` | `affection` |
| 轻轻庆祝／开心庆祝 | `celebration` | `joy` |
| 专注解决／思考好奇 | `thinking` | `neutral` |
| 安静休息 | `rest` | `neutral` |
| 你好、问候 | `greeting` | `affection` |
| 谢谢、感谢 | `thanks` | `affection` |
| 害羞、可爱等通用表达 | `general` | `affection` |

查询 `q` 来自固定表达词表，不截取用户原话，也不接受模型直接指定 URL、场景或上下文。发送 `scene`、`emotion`、`maxIntensity`、`limit=8`，存在限制时另发送逗号分隔的 `contexts`。当前上下文从本轮和最近两条用户消息中保守识别冲突、严肃倾诉、哀伤、医疗或安全话题；这不是完整自然语言分类器，无法可靠识别表达场景时跳过远程搜索。

疲惫、倾诉、任务等原有场景不自动预取远程表情，即使结果有 comfort 标签也不放宽。明确请求仍不能绕过语义约束；识别为严肃倾诉、哀伤、医疗／安全话题时不检索远程图。冲突上下文传给图库并在客户端再次检查。`general` 只匹配自身，强度为上限，用户情绪不直接复制为图片表达情绪。

`media.prepare()` 先取启用且不在近期排除列表中的本地候选，复用现有 `rankText` 非零相关性匹配及策略判断；已有合适匹配就跳过远程预取。本地不足且策略允许时，最多一次受限搜索。验证候选的含义、名称、标签、完整枚举数组、禁用上下文、强度、示例、原图属性、revision、updatedAt、score 和同源 URL。丢弃错误项，保留服务端排序，去重并排除近期 ID；不降级接受只有 url／alt／animated 的旧搜索结果。

有效候选使用原有算法生成 `remote-${sha256(完整检索地址 + 换行 + 图片URL)}`，保存至原 `remote_stickers.value` JSON。图库 `stk_*` ID 另存为 `galleryId`，不作为聊天附件 ID。保存的资料只含已知非敏感字段，不保存模型上下文或 Key，不需要数据库表结构迁移。

主模型看到的候选总数不超过 16，本地优先并给远程候选预留空间。远程候选展示兼容 ID、简短含义、场景、表达情绪、强度、完整禁用数组和示例，不提供图片地址或 Key。名称、说明、示例全部标为不可信资料。模型仍用原 `<qiyi-media>` 协议，只能选择本轮候选；停用本地资源、无效 ID、图库原始 ID、任意 URL、已不符合最新策略的远程候选都不能成为附件。

未预取时，`stickerQuery` 先在本轮本地候选内匹配，仍无合适图片且已有结构化场景时，最多一次远程检索并按图库排序选首个安全结果。模型检索词不改变程序识别的限制，也不会原样上传。已预取时不再次检索；空结果、401、403、429、5xx、无效响应和超时都不影响正文。主模型仍只调用一次，预取等待计入整条聊天延迟。

## 图片代理与历史

浏览器只通过 `/api/media/sticker-image?id=<leaf/upload/remote ID>` 读取。`public/media.js` 继续由 ID 重建同源 URL，保留动图点击加载、失败说明和移动端布局；新附件使用图库 alt 作为替代文本，旧附件缺 alt 时使用名称。

代理按已登记的可信引用查找图片，验证当前服务身份和来源。与当前配置检索来源相同的图像请求携带当前 `Authorization: Bearer <Key>`，额外允许的旧来源永不接收它。GET 与 HEAD 都访问上游并验证权限；Range 不转发，完整读取，不提供缓存绕过。图片禁用后是否仍可读由图库 `images:read` 契约保证。

所有网络请求禁止重定向，默认 6 秒超时。候选 JSON 上限 512 KiB；图片沿用 4 MiB、4096 单边和 1600 万像素限制及真实格式检查。新图 GET 的 Content-Type 必须与图片格式一致；HEAD 验证受支持的 MIME 和长度，不读正文。鉴权／限流等错误保留适当状态并使用通用说明；不把 HTML、JSON、跳转当成图片，不透传上游 Cookie、凭据或内部头。浏览器响应保持 no-store、nosniff。

Key 轮换时只更新服务进程凭据，完整服务地址、图片 URL、附件 ID 保持不变，历史读图使用新 Key。历史渲染不重新搜索、不重判语义；旧 `remote-*` 引用即使没有新增语义字段仍按原路径读取。本地 `leaf-*`、`upload-*` 的 BLOB 与 ID 原样保留。没有持久离线缓存，断网时远程历史图可能不可读。

## 验证

`tests/sticker-gallery.test.mjs` 覆盖枚举映射、查询最小化、完整资料、禁用与强度、通用场景非通配、本地优先、候选总量、白名单、近期排重、一次检索、错误降级、预取超时、最新状态、Key 轮换和旧来源隔离。超时测试使用 20ms 测试期限，验证预取结束后只调用一次主模型；不等于真实公网响应时间承诺。

`tests/media-http.test.mjs` 覆盖受保护 GET／HEAD／Range、搜索与读图权限分离、Key 轮换、no-store、响应头隔离和任意 URL 无法代理。`tests/media-browser.spec.mjs` 覆盖语义 alt、历史重载、图片 Key 失效占位、同源网络请求、动图及手机显示。所有图库调用均为隔离模拟，不调用生产图库或修改生产聊天。
