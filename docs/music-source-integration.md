# 使用现有音乐平台作为音乐源

> 实现更新（2026-10-25）：本地图库、聊天媒体附件、音乐服务适配和全局播放器已实现并通过模拟服务自动化验证；当前配置及接口说明见 [README](../README.md#表情包与音乐配置)。以下保留调研时的结论与设计依据。

检查日期：2026-10-24。用户已指定 `D:\al\erp\music` 为本项目的音乐来源。本文件依据该项目的实际源码整理接口与接入方式，不再把新的第三方音乐 API 作为第一版接入前提。

## 检查结论

该项目可以作为歌曲推荐与背景播放的来源：它已有 QQ 音乐和网易云两套客户端、统一搜索接口、在线音频流、本地曲库及封面接口，并提供收藏、歌单与歌词能力。推荐复用其 HTTP 服务，由栖忆增加适配器与全局播放器，不把两个 Python 客户端复制进 Node.js 项目。

登录状态和上游音频地址解析继续由音乐服务处理。栖忆记录稳定歌曲标识，在实际播放时访问音乐服务，避免保存会过期的上游 CDN 播放地址。

## 实际接口

| 已有接口 | 参数与响应概要 | 栖忆用途 |
| --- | --- | --- |
| `GET /api/status` | 返回 `default`、`auth`、`sources`；来源包含 `qq`、`netease`。 | 手动测试连接，展示服务与来源状态。对前端只返回所需状态，不转发账号标识。 |
| `GET /api/search` | `keyword`、`source`、`num`、`page`；返回 `songs`。 | AI 推荐候选与用户搜索。 |
| `GET /api/stream` | `songmid`、`source`、可选 `quality`；转发音频及 Range 请求。 | 在线歌曲播放、背景音乐播放。 |
| `GET /api/library` | 返回 `count`、`files`；含文件名、标题、歌手、专辑、时长与封面状态。 | 使用已有本地曲库，不需要重新上传或复制歌曲。 |
| `GET /api/local_play` | `name`；使用条件响应提供本地文件。 | 本地歌曲播放及进度拖动。 |
| `GET /api/local_cover` | `name`；提供内嵌封面。 | 本地歌曲卡片与播放器封面。 |
| `GET /api/fav` | 已认证用户的收藏；无鉴权模式需要显式 `user`。 | 后续作为个人偏好和候选来源。 |
| `GET /api/playlists`、`GET /api/playlist` | 用户歌单列表，以及指定 `id` 的曲目。 | 后续播放已有歌单。 |
| `GET /api/lyric` | `songmid`、`source`；返回 `lyric`、`trans`。 | 可选的歌词视图，非第一版背景播放的必要条件。 |

主要实现位于音乐项目 `app.py` 的 `api_status`、`api_search`、`api_stream`、`api_library`、`api_local_play` 等函数；歌曲归一化字段可以直接参考其 `web/app.js`。

在线搜索返回字段为 `songmid`、`songname`、`singer`、`album`、`duration`、`cover` 等。栖忆可统一为：

```json
{
  "kind": "online",
  "source": "qq",
  "songmid": "由搜索接口实际返回的标识",
  "title": "实际歌名",
  "artist": "实际歌手",
  "album": "实际专辑",
  "duration": 240
}
```

本地歌曲使用 `kind: local` 与曲库返回的 `name`，不能将其强行转成在线 `songmid`。在线标识必须同时保留 `source`，避免 QQ 和网易云的 ID 混用。

## 连接状态与地址

- `app.py` 主程序实际默认监听端口是 `10001`，默认绑定地址为 `0.0.0.0`。
- 部分 `test_*.py` 中的 `BASE` 仍是 `http://127.0.0.1:5000`，与主程序默认值不同，不能据此认定服务使用 5000。
- 安卓源码包含默认服务地址 `http://123.60.216.193:10001`；它是源码中的默认配置，不能据此认定为用户当前的实际部署地址。
- 本次只读探测中，本机 `10001` 和 `5000` 均返回连接拒绝；安卓默认地址的连接中断，因此尚未核实线上服务可用性，也没有验证真实搜索或音频播放。
- 当前 `downloads` 中检查到 4 个 MP3 文件，可用于服务启动后的本地曲库联调；检查时未读取或复制音频内容。

用户已确认：接入地址默认留空，后续再在设置中填写。音乐源选型已确定，不再要求先确认实际部署地址。

未配置时显示“音乐服务未配置”，不自动尝试本机端口、安卓默认地址或其他备用服务，不发起音乐搜索、曲库或播放请求，也不显示虚假的已连接或可播放状态。普通聊天照常工作。后续填写非空地址后可手动测试连接，实际播放仍由用户点击触发。

## 鉴权

音乐服务在配置了主密钥或密钥表非空时启用鉴权，支持 `X-API-Key` 请求头，也兼容 URL 查询参数 `key`。启用鉴权后，密钥还会绑定音乐服务中的用户身份。

栖忆应在 Node.js 服务进程内保存音乐 API Key，向音乐服务发送 `X-API-Key`，不将其写入聊天、模型上下文、音频 URL 或浏览器本地存储。源项目现有 Cookie 文件由其自身使用，栖忆不需要读取或导入这些文件。

如果服务部署在公网，连接宜使用 HTTPS；源码中的默认公网地址目前为 HTTP，不能把“密钥放在请求头”当成传输加密。

收藏和歌单应使用密钥对应的身份；无鉴权模式下的 `user` 需要显式配置。第一版可以先接状态、搜索、曲库和播放，不必替音乐服务新建用户或变更收藏、歌单。

## 建议的接入链路

1. 浏览器只请求栖忆本域的 `/api/music/...`。
2. Node.js 适配器按固定接口映射访问已配置的音乐服务，并在服务端附加鉴权头。
3. 音频使用流式转发，传递 Range 请求及必要的类型、长度、范围响应头；用户停止播放时及时取消上游读取，不把整首歌曲读入内存。
4. 本地封面通过受控路由获取；在线封面单独验证来源，不提供可抓取任意 URL 的图片代理。
5. 浏览器只接收统一歌曲信息、栖忆自己的播放路径与真实播放状态，不需要知道音乐服务的 Key 或 Cookie。

这能避免音乐源鉴权和跨域逻辑散落在聊天界面中。音乐地址只能来自应用配置；模型与用户消息不能改变代理目标。

## AI 推荐和背景播放

- AI 先提出检索意图，适配器从真实搜索结果中取得候选，再生成或校验歌曲推荐卡片。没有结果时保留文字，不虚构 `songmid` 或可播放状态。
- 本地优先时，先查询现有曲库；曲库不足时使用 QQ 或网易云搜索。当前曲库元数据没有统一情绪标签，场景推荐需后续补充标签或利用用户已有歌单，不能假设源服务已经提供情绪推荐。
- 用户点击卡片可以播放、加入当前播放队列或设为背景音乐。后两者先是栖忆的会话内操作，不自动调用源平台的收藏、歌单写入或下载接口。
- 全局音频元素保持在 `#main` 外，页面切换、聊天刷新和记忆渲染不会重建播放器。
- 音频默认由用户点击启动；AI 可以推荐音乐，不因普通回复直接覆盖当前播放。是否允许 AI 自动换曲仍是单独的设置。
- 在线浏览器播放可参考源项目已用的 `quality=320` 或 `quality=128`；最终是否可播由源服务返回及浏览器解码结果确定。源项目支持的文件后缀不等于所有浏览器都支持对应编码。

## 联调与验证顺序

1. 用实际地址手动测试 `/api/status`；若返回 401，则通过设置或环境变量提供音乐 API Key，再确认授权结果。
2. 只读获取本地曲库，核对曲目数量和字段；对其中一首歌请求小段 Range 数据，验证播放与拖动所需行为。
3. 分别验证 QQ 和网易云搜索，确认返回的来源、歌名、歌手和 ID 对应正确。
4. 在用户点击播放后验证在线流；无可播放资源、鉴权失败、超时及上游错误应显示不同状态。
5. 验证暂停、切歌、循环、页面切换连续播放、手机布局及关闭播放器后的上游取消。
6. 最后再接入 AI 回复歌曲卡片，测试未知候选、旧记录恢复和音乐源暂不可用时的文字回退。

本次完成的是源码检查、接口核对和连接探测。没有运行会保存、删除歌曲的源项目测试，没有读取账号 Cookie、数据库密钥或修改音乐项目。
