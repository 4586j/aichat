# 回应联动实现说明

联动覆盖用户状态到文字、表情、歌曲和宠物的协调表达。配置见 README 和内置 start／music／stickers 指南，普通用户无需调整协议。

## 一次模型请求与本轮状态

每次聊天仍只调用一次模型。原有 qiyi-state 和 qiyi-media 协议继续共存：模型生成文字、状态和媒体意图，服务端先用 chatState.preview 校验本轮原话并合并最新的有效手动项，再形成媒体策略。预览不写数据库；无正文、模型失败时不保存状态或占用推荐间隔。

在模型请求前，提供已有有效状态、独立开关、本轮推荐资格、候选表情的场景和强度，以及最多六条已确认活跃偏好（各最多 240 字）。偏好限置信度至少 0.7、手动添加或已核对正文的记录，作为参考数据提供，不作为指令。模型在同一请求内结合当前用户文字形成回复；返回的意图仍须通过程序检查。用户手动备注不加入联动提示。

在收到模型输出后，以及写入消息事务前，重新检查最新手动状态、开关和会话静音。处理中用户关闭联动或暂停主动推歌时，不会因为采用旧请求快照而显示已被禁止的自动附件。已开始的可选查询无法撤回，但返回后会再筛选。最后将用户消息、状态、助手正文、附件和 responseBehavior 依据在一个事务内保存。

## 需要优先的场景

public/response-scenes.js 由服务端和浏览器共用，避免宠物和媒体各自解释状态。

1. 需要任务或建议：专注解决，不主动配图或推歌。
2. 精力疲惫：安静休息，采用低强度休息／安慰表情。
3. 想被倾听，或失落、担心、烦躁：温和陪伴，采用轻柔素材，不主动推歌。
4. 开心／兴奋且角色不是认真表达、主动程度不是少追问：短暂庆祝。
5. 无有效状态或关闭状态辅助：自然交流，不因不确定情绪主动推歌。

情绪、精力和需要依然是分开的字段。相同情绪可以对应不同需要，手动状态优先。熟悉程度不决定活跃频率，只通过已确认偏好帮助个性化选择。

## 媒体选择与间隔

表情每次最多一张，自动表情不连续出现，近期两条助手消息中用过的图片从普通候选中排除。明确索要表情可绕过普通冷却和场景限制，仍要从本轮真实候选中选图。sticker_profiles 按素材保存场景和 1～3 强度，旧上传素材默认通用／2，内置素材通过幂等初始化补充标签。休息、倾诉等场景只自动采用已标注低强度本地素材，无法分类的联网结果不自动用于这些场景。其他场景和明确请求保留本地优先、联网补充方式。

主动音乐按该会话成功的助手回复计算：第一次最早在第 5 次，之后最近 4 次回复没有歌曲推荐时才有资格；疲惫或少追问时窗口为 10 次。任何实际歌曲／待查询卡片都会进入后续间隔，收起卡片不会重置计数。失败模型请求不占次数。间隔由保存的消息派生，重启不重置。

需要倾听、任务、建议，状态未知、音乐地址为空、联动关闭、本会话静音或明确拒绝音乐时不主动推荐。用户本轮明确要求点歌／推荐可绕过普通窗口和会话静音，仍服从音乐总开关。明确需求采用保守的中文／英文请求识别；讨论音乐服务配置不当作点歌。模糊说法不授予绕过限制的资格。

一条回复默认只突出表情或歌曲。明确要求表情时，优先满足表情；明确要求音乐时优先歌曲；只有明确要求两者时才同时输出。模型不返回合适意图时可只给文字，系统不为达到推荐频率硬插歌曲。音乐仍使用原有平台适配器，不新增音频情绪、歌词或 BPM 分析；检索与播放是独立行为，推荐和反馈均不播放、切歌、调音量或修改队列。

## 独立开关和反馈

response_settings 保存 stickerLinked／musicLinked／petLinked 和 revision。更新采用 expectedRevision 乐观锁，冲突返回 409，界面保留尚未保存的选择，用户点击重新读取后再编辑。关闭联动只限制自动搭配，明确索要表情／音乐仍可响应，原有媒体总开关继续生效。宠物联动关闭后采用普通等待、回复与实际听歌表现，名字和动效偏好不变。

消息的 musicFeedback 字段保存 skip／mute，空值表示显示。skip 只收起该条歌曲，restore 恢复卡片；均保留原始附件。conversation_response 保存该会话 musicMuted，mute 同时收起该条并暂停会话主动推歌，unmute 恢复资格。新会话独立、刷新和重启保留，反馈不生成模型请求、不改写情绪和长期记忆。明确点歌在静音时仍可响应。

## 本地接口

- GET /api/response-settings：读取三个独立开关和修订号。
- PUT /api/response-settings：提交 expectedRevision 及需要修改的布尔字段。
- POST /api/conversations/:id/music-feedback：提交 action=skip／mute／restore 和 messageId；action=unmute 无需消息编号。只允许操作该会话的助手歌曲消息，返回更新后的消息、会话静音和当前状态。
- 原有表情上传／编辑接口新增 scene 与 intensity 字段，完整验证后写入。

原有本机监听、Host／Origin 和 JSON 请求验证继续保护这些接口。responseBehavior 保存当时的场景和经验证的状态引用，供历史消息“本轮回应依据”展示；当前宠物表现依据仍有效的状态计算，过期后恢复自然交流。

## 验证

tests/response-policy.test.mjs 覆盖同轮状态、证据、手动优先、开关、5／10 次窗口、明确点歌、静音隔离、反馈幂等、失败回滚、素材标签和重启。tests/response-policy-browser.spec.mjs 验证点击播放、收起／恢复、静音／恢复、独立设置、状态依据及 320／390 像素手机操作。模型、音乐和图片服务采用离线模拟，不调用真实服务。
