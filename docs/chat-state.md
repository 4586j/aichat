# 对话状态实现说明

本功能覆盖六项：用户情绪、精力、当前需要，AI 角色表达状态、主动程度，以及按角色计算的熟悉程度。使用方式见 README 和内置配置指南 `start`。

## 状态作用域

前五项按会话保存到 SQLite `chat_states`，每项独立记录更新时间、30 分钟有效期、来源、判断把握和证据。读取或拼装模型上下文时即时排除过期项；界面按服务端时钟偏差计算过期时间，并重新读取。过期表示不再使用，数据库中的旧值不会因为时间经过而立即物理删除，可通过“清空本会话状态”清除。没有记录时默认用户状态未知，角色跟随人设，主动程度正常。

`assist` 要求模型辅助判断；`manual` 只采用手动指定项；`off` 清空并停止使用短期状态和熟悉上下文。关闭辅助不删除记忆或角色熟悉程度设置。自动结果不能覆盖仍有效的手动项，手动短期状态也在 30 分钟后过期。用户选择的状态只用于后续回复，不改写已经生成的文字。

## 一次聊天请求与可追溯依据

每次普通聊天仍只调用一次 `/chat/completions`。自动模式下，系统提示词要求在正文和可选媒体块之后追加一行：

```text
<qiyi-state>{"energy":{"value":"low","confidence":"high","evidence":[{"messageId":"current","quote":"今天好累"}]},"need":{"value":"listen","confidence":"high","evidence":[{"messageId":"current","quote":"先别给我建议"}]}}</qiyi-state>
```

仅识别正文末尾、代码和注释之外的独立行。元数据最多 8000 字符；解析失败时丢弃该可选元数据，保留正文。状态块在媒体块前后均可处理，与原有表情和歌曲卡片协议共存。只有元数据、没有回复正文时仍视为模型回复失败，不保存消息和状态。

字段采用固定枚举。情绪最多两种且已知情绪必须有 1～5 整数强度；判断把握只能是 low、medium、high。每项最多引用两段不超过 120 字符的连续用户原话，消息编号必须来自该会话已提供的用户历史或本轮 current，不能引用助手文字、其他会话、记忆或知识库作为状态证据。仅接受最近 30 分钟内、最多八条提供给模型的用户历史原话和本轮文字。引用旧发言时以原话时间计算有效期，重复引用不会续期；低把握结果保留依据但使用未知／默认值。枚举、强度或证据错误的项目独立忽略。校验原话能确认来源，不能证明模型对原话含义的理解一定正确，因此 UI 明确标注“AI 推测”并允许修改。

先剥离状态块，再交由现有媒体解析器处理；存入聊天历史的助手消息不含状态协议。用户消息、助手正文和状态更新在同一 SQLite 事务内写入。current 引用此时替换为真实用户消息编号。失败请求不写入状态。每轮提交时重新读取手动设置和模式，处理中途切换关闭或手动修改仍优先。

模型接收当前有效状态的枚举值、强度和来源，以及熟悉阶段、分数和已确认资料数；不附带手动备注。正常聊天历史和原有记忆召回机制继续工作。状态只能指导措辞、长度和聊天中的追问，不能授予发信、播放音乐或修改设置的权限；熟悉程度不代表信任或好感。

## 熟悉程度

`familiarity_state` 按角色保存可选人工分数和依据。未人工指定时，动态计算该角色置信度至少 0.7、活跃的非摘要记忆，按 NFKC、大小写和连续空白归一后去重，仅计入 source 为 manual 或有 confirmedAt 的条目。手动新建记忆，以及在编辑器中核对并保存正文，会记录 confirmedAt；仅固定、归档、恢复不会确认未核对过的自动记忆。

分数 = min(100, 已确认不重复资料数 × 8 + 资料类别数 × 3 + min(10, 重复提及资料数) × 2)。0～24 初识，25～59 逐渐熟悉，60～100 熟悉。资料归档、删除或编辑后重新计算。时间流逝与单纯聊天次数不加减分，自动模型状态元数据中的熟悉分数不会被采用。手动指定时必须提供整数分数及依据；取消后恢复自动计算，人工分数不会随短期状态过期。

## 本地接口与并发编辑

- `GET /api/chat-state?personaId=...&conversationId=...`：读取当前状态、熟悉依据、选项和服务端时间；conversationId 可省略，不创建会话。
- `POST /api/chat-state`：提交 `{personaId, conversationId, patch}`。patch 支持 fields、reset、mode、clear、familiarity，必须携带 expectedManualRevision；修改熟悉程度还需 familiarity.expectedRevision。

先完整校验参数及版本，再原子写入。短期状态手动版本独立于自动更新版本，避免普通自动判断让已打开的编辑器失效。其他手动修改引起的冲突返回 409，保留用户编辑内容，要求显式重新读取；角色熟悉覆盖使用独立修订号。只修改熟悉程度不创建空会话；首次手动保存短期状态会创建会话，前端迁移原草稿。模型分析不会创建额外会话或后台请求。

## 验证范围

`tests/chat-state.test.mjs` 验证来源、协议、模型请求次数、过期、手动优先、并发、隔离、熟悉公式、重启持久化和 HTTP 边界。`tests/chat-state-browser.spec.mjs` 覆盖六项展示、依据展开、手动修改、草稿、熟悉覆盖、冲突和 320／390 像素手机布局。模拟模型测试验证应用行为；真实模型是否遵守可选元数据格式、判断是否符合用户感受，仍取决于所配置的模型，用户可以随时手动调整。
