# 宠物表情与自然动作

四款宠物保留 `v1` 的毛绒质感、品种、配色、比例和配饰。日常表情和轻微动作沿用对齐到原图的面部素材与连续局部形变；招手、伸懒腰、吃点心和跳跃改用真正改变肢体姿势的完整身体帧。不引入动画框架、外部图片服务或运行时生图。所有动画只用于本地展示，试玩不调用模型、不增加陪伴点数；正式互动继续由原有接口记录。

## 表情与状态

`public/pet-motion.js` 的 `petPresentation()` 统一决定面部表情与动作；`public/response-scenes.js` 继续统一解释当前有效对话状态，手动状态和当前需要的优先级保持不变。

| 条件（由高到低） | 表情 | 动作 |
| --- | --- | --- |
| 用户摸摸、喂点心、玩耍 | 开心 | 侧蹭；捧点心、送到嘴边、咀嚼；预备、起跳、落地 |
| 用户点击动作试玩 | 动作对应表情 | 招手、伸懒腰、张望、动耳、摆尾／蹭蹭、轻蹦、抖毛 |
| 疲惫／休息 | 困倦放松 | 身体静止，可慢慢眨眼 |
| 倾诉／温和陪伴 | 温柔陪伴 | 极轻呼吸，暂停偶发小动作 |
| 任务／建议 | 专注好奇 | 极轻呼吸，暂停偶发小动作 |
| 正在等待聊天回复 | 专注好奇 | 安静等待 |
| 开心场景收到回复 | 开心 | 一次低幅度庆祝 |
| 普通回复／错误提示 | 温柔陪伴 | 轻微点头／温和陪伴 |
| 实际音乐播放 | 自然 | 轻微点头 |
| 其他 | 自然 | 呼吸，偶发小动作 |

主动互动和试玩保留约 2.4～3.6 秒，按动作时长加短暂收尾，新的主动动作可以替换它；聊天回复或错误不会打断正在进行的主动动作。结束后重新计算当前状态，恢复倾诉、休息、任务、等待或实际音乐表现。连续点击同一种互动也会重新开始动作，但加分仍由原有服务端冷却和 `applied` 字段决定。试玩没有请求接口，不产生点数或互动记录，也不会改写情绪和偏好。

开心表情只短暂出现；不会一直闭眼笑，也不会因用户负面情绪切成哭泣或生气脸。短暂表情返回自然时至少停留约 1.4 秒；新的陪伴需要和主动互动可以立即替换表情。相同状态的普通界面刷新不重置眨眼或动作。

音乐监听现有 `<audio>` 的 `playing`、`pause`、`ended`、`emptied`、`error`、`waiting` 事件；仅 `playing` 启动听歌表现，其他事件停止。恢复播放时再由 `playing` 恢复。不检测 BPM、不自动播放、不切换队列，静止或专注等当前需要仍优先。

## 眨眼与动作节奏

- 间隔随机约 4～8 秒，半闭 50ms → 闭眼 100ms → 半闭 80ms → 睁眼；实际显示按绘制帧率取整。
- 约 12% 概率多眨一次，中间停留约 150ms，最多连续两次；之后恢复长间隔。开心表情本身闭眼，不叠加眨眼。
- 眨眼素材只有眼睛与附近毛发的透明补片，覆盖当前表情的眼睛，嘴巴和身体不变化。
- 首次待机约 0.8～1.6 秒开始动作，打开小窝时可提前到约 0.45 秒；完整动作约 0.5～1.36 秒，其他小动作约 2.1～3.2 秒，结束后再停留 2～5 秒。按宠物随机打乱完整动作列表，一轮中每种只出现一次，新一轮也避免首尾重复。
- 猫：摆尾、张望、伸懒腰、招手、动耳、蹭蹭、抖毛；柴犬：摆尾、招手、轻蹦、张望、动耳、伸懒腰、抖毛；兔子：动耳、张望、伸懒腰、招手、蹭蹭、轻蹦、抖毛；狐狸：动耳、张望、摆尾、招手、伸懒腰、蹭蹭、轻蹦。自然状态下会随动作短暂切换合适表情，再恢复自然。
- 小窝的“看看它的小动作”提供即时试玩。兔子用“蹭一蹭”替代“摇摇尾巴”，每款各 9 个按钮，包括“尝点心”“开心跳跳”；试玩同样遵循轻动效开关和系统减少动态效果。关闭轻动效后按钮禁用，系统减少动态效果时只显示静态表情并说明原因。试玩点心与玩耍也不增加互动记录。
- 倾诉、任务、等待、休息和主动互动期间暂停偶发动作。互动、点头和歪头使用起止归零的包络，脚部和画布边界固定，不积累漂移。

呼吸、耳尾、张望、侧蹭、抖毛仍使用原图的连续三角网格形变，眼睛、嘴巴与毛发一起移动。完整身体动作则直接裁取当前姿势，避免用拉伸一张坐姿原图来代替举爪、站高或腾空。完整动作资源失败时，仍可使用已有局部动作作为回退。

无需把毛绒耳朵和尾巴硬裁成独立贴片，也不会因转动图层露出空洞。采样保留相邻单元的余量，避免手机缩放下出现网格接缝；测试采样每个动作的完整周期，检查每个三角形保持正向、局部移动有界，防止放大动作后出现翻折。

## 完整身体动作

`public/pet-clips.js` 保存动作行、姿势顺序和每帧时长。四款各有一张 `2304 × 1536` 透明 WebP，6 列 × 4 行，每格 384px：招手、伸展、进食、跳跃各六个清晰的关键姿势。普通姿势按约 85ms 切换（约 12 个姿势／秒），不再把六张图拖长到三秒左右。招手轮换两次，玩耍有两次起跳，轻蹦与庆祝只有一次；伸展顶点有约 425ms 的有意停留，期间仍有连续的伸展变化。

招手会举起实际爪子；伸展会改变前肢、肩膀与躯干姿态；进食会捧起饼干、送到嘴边、咬下并收爪；玩耍包含蹲伏、推地、空中姿势与落地。动作本身包含对应面部表情，不把原坐姿的眨眼补片覆盖到已经移动的头上。动作期间暂停补片眨眼，回到原姿势后重新等待。

完整动作保留清楚的原始脸部、毛发和轮廓，每次只绘制一个姿势；在这个姿势上连续增加约 0.7 度以内的重心摆动、0.6% 以内的呼吸，以及伸展时约 1.8% 的舒展变化，绘制时以脚底为支点。首尾短暂过渡使用预乘透明度相加，避免身体突然变透明。动作时长与较长的互动说明分开，动作先自然完成，说明继续保留供阅读。连续点击仍会重新开始，普通刷新不会重播。

姿势变化的采样率与画布刷新率不同：关键姿势约 12fps，连续重心、呼吸等变化的绘制目标为桌面 60fps、手机 30fps。六个关键姿势仍有素材密度的上限，不能等同于每秒生成 60 个完整肢体姿势。所有计算都是本地 Canvas，不增加运行依赖、网络服务或额外动画数据。

`scripts/build-pet-actions.mjs` 只在开发期整理生成图：按网格裁切、保留真实 alpha、清除边缘邻格的不相连碎片，按同一比例注册全部姿势。非腾空姿势校准脚底；起跳与腾空保留离地量。不会把每帧单独放大填满格子，否则伸展与跳跃会被缩放抵消。脚本检查有效身体不贴输出边缘。奶油猫的招手单独重做，保证始终抬同一只爪子。

静止图与完整动作必须使用同一个显示标尺。原动作图为了容纳最宽的展开姿势，曾把兔子的普通坐姿也缩小到约 295px，而静止图为约 340px，切换时会明显小一圈。`scripts/build-pet-framing.mjs` 从原始 PNG 和动作图的每行首尾坐姿计算统一缩放、中心与脚底，输出 `public/pet-framing.js`。每行只使用一个校准变换，保留该行蹲伏、伸展与腾空的真实变化，不对每一帧分别填满画布。

静止与动作共用能容纳最大耳尾、抬爪和微动的相机范围，并留出 16px 的保护空间。画布通过以脚底为基准的少量外扩补回静止形象的原显示大小，布局尺寸和回退 PNG 保持原有显示比例。这样不会通过缩小静止宠物来掩盖问题，也不会因把动作直接放大而裁掉耳朵。更换或重建动作图后应重新运行构图校准脚本。

```powershell
node scripts/build-pet-actions.mjs <pet-id> <6x4-sheet.png> [optional-3x2-wave-sheet.png]
node scripts/build-pet-actions.mjs --preview
node scripts/build-pet-framing.mjs
```

sharp 的开发环境要求与表情整理脚本相同，不增加应用运行依赖。完整提示见 [动作提示记录](pet-action-prompts.md)，四款动作关键姿势见 [预览图](assets/pet-actions-v3.webp)。参考了开源播放器的本地帧表与有限动作调度思路，素材由内置 imagegen 生成，没有复制开源桌宠的角色图片或播放器实现。

## 素材、绘制与暂停

每款使用一个 `2688 × 384` WebP 条带：自然、温柔、开心、专注、困倦五个 384px 全身画面，之后是半闭与闭眼两个透明眼部帧。五个画面除面部补片外均来自相同的原图。四张条带合计 570,896 字节（约 558 KiB），每张小于 200 KB。生成和注册流程见 [素材记录](pet-assets.md) 与 [完整生成提示](pet-animation-prompts.md)。

只按需加载选中的宠物，访问过的四款各缓存一次。完整动作图仅在有可见形象、允许动画、当前状态需要时加载；初次静止、倾诉、专注和休息不下载它，主动试玩可触发加载。完整图与表情图分开，避免只看静态形象也必须下载动作图。用一个共享离屏画布完成当前宠物的表情合成、过渡或变形，再复制到可见的顶部头像、聊天卡片和小窝，避免每个位置重复计算。桌面目标上限约 60fps，700px 以下约 30fps；保留调度余量，避免刷新周期取整导致重复绘制或漏帧。显示画布 DPR 上限 2、边长上限 440px，实际素材分辨率为 384px。

关闭“开启轻动效”或系统 `prefers-reduced-motion: reduce` 时，取消动画帧调度，只在状态／布局变化时绘制静态表情。页面隐藏和所有形象离开视野时停止连续绘制；不可见期间不推进动画时钟，回来后重置眨眼和小动作的等待时间，不追赶积压帧。已经过期的互动反馈不会在回到页面时重新播放。原有 CSS 星光只响应主动互动，同样遵循动效开关和系统偏好。

新节点由 `MutationObserver` 接入，共享当前状态；删除的节点会解除 `IntersectionObserver` 订阅。完整动作图缺失或尺寸不符时保留五种表情与原有局部动作；表情资源缺失、尺寸不符或画布不可用时保留原始 PNG；原图也失败时使用原有替代提示。资源采用显式静态路径白名单、正确 WebP MIME 与版本化长期缓存，不能请求任意路径。

## 验证范围

`tests/pet-motion.test.mjs` 检查需要／互动／音乐优先级、单次和双次眨眼、动作轮换与暂停、可见幅度、预备／离地／落地阶段、完整周期网格稳定性、素材大小及 HTTP 缓存。`tests/pet-clips.test.mjs` 额外检查完整动作有限播放、六个姿势都被访问、单跳与双跳、alpha、图幅和静态服务白名单。`tests/pet-motion-browser.spec.mjs` 在离线 Chrome 中检查实际画布内容、四款各四种完整动作、逐帧顺序、眨眼不错误叠加、按需缓存、动效开关、系统偏好、隐藏／离屏暂停、素材缺失与尺寸错误回退、试玩零请求／零加分、真实聊天恢复，以及 320／390px 手机布局。使用受控时钟验证等待时间，不依赖真实模型或音乐服务；真实音乐播放还由原有宠物与媒体浏览器测试覆盖。

`tests/pet-cadence-browser.spec.mjs` 检查同一姿势停留期间的实际画布持续更新、四款姿势轮廓保持清楚、减少动态效果后停止、以及没有新增素材请求。`node scripts/profile-pet-motion.mjs` 可在不改动用户数据的临时服务中采样桌面与 4 倍 CPU 限速的手机视口；采样只代表本机环境，不保证所有手机的实际帧率。

`tests/pet-framing-browser.spec.mjs` 对四款宠物的四种动作测量实际 CSS 像素尺寸，比较普通坐姿进入／退出动作时的宽高和脚底。静止画布也单独与原 PNG 的真实显示尺寸比较，避免通过一起缩小两套素材来让检查通过；另检查抬爪、展开耳朵和跳跃全周期没有贴到画布边缘。
