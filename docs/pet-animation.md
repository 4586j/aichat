# 宠物表情与自然动作

四款宠物保留 `v1` 的毛绒质感、品种、配色、比例和配饰。日常表情和轻微动作沿用对齐到原图的面部素材与连续局部形变；招手、伸懒腰、吃点心和跳跃改用真正改变肢体姿势的完整身体帧。不引入动画框架、外部图片服务或运行时生图。所有动画只用于本地展示，试玩不调用模型、不增加陪伴点数；正式互动继续由原有接口记录。

## 表情与状态

`public/pet-motion.js` 的 `petPresentation()` 统一决定面部表情与动作；`public/response-scenes.js` 继续统一解释当前有效对话状态，手动状态和当前需要的优先级保持不变。

| 条件（由高到低） | 表情 | 动作 |
| --- | --- | --- |
| 用户摸摸、喂点心、玩耍 | 开心 | 侧蹭；捧点心、送到嘴边、咀嚼；预备、起跳、落地 |
| 用户点击动作试玩 | 动作对应表情 | 招手、伸懒腰、张望、动耳、摆尾／蹭蹭、轻蹦、抖毛 |
| 疲惫／休息 | 困倦放松 | 身体静止，可慢慢眨眼 |
| 倾诉／温和陪伴 | 温柔陪伴 | 极轻呼吸，暂停偶发小动作 |
| 任务／建议 | 专注好奇 | 极轻呼吸，暂停偶发小动作 |
| 正在等待聊天回复 | 专注好奇 | 安静等待 |
| 开心场景收到回复 | 开心 | 一次低幅度庆祝 |
| 普通回复／错误提示 | 温柔陪伴 | 轻微点头／温和陪伴 |
| 实际音乐播放 | 自然 | 轻微点头 |
| 其他 | 自然 | 呼吸，偶发小动作 |

主动互动和试玩保留约 2.4～3.6 秒，按动作时长加短暂收尾，新的主动动作可以替换它；聊天回复或错误不会打断正在进行的主动动作。结束后重新计算当前状态，恢复倾诉、休息、任务、等待或实际音乐表现。连续点击同一种互动也会重新开始动作，但加分仍由原有服务端冷却和 `applied` 字段决定。试玩没有请求接口，不产生点数或互动记录，也不会改写情绪和偏好。

开心表情只短暂出现；不会一直闭眼笑，也不会因用户负面情绪切成哭泣或生气脸。短暂表情返回自然时至少停留约 1.4 秒；新的陪伴需要和主动互动可以立即替换表情。相同状态的普通界面刷新不重置眨眼或动作。

音乐监听现有 `<audio>` 的 `playing`、`pause`、`ended`、`emptied`、`error`、`waiting` 事件；仅 `playing` 启动听歌表现，其他事件停止。恢复播放时再由 `playing` 恢复。不检测 BPM、不自动播放、不切换队列，静止或专注等当前需要仍优先。

## 眨眼与动作节奏

- 间隔随机约 4～8 秒，半闭 50ms → 闭眼 100ms → 半闭 80ms → 睁眼；实际显示按绘制帧率取整。
- 约 12% 概率多眨一次，中间停留约 150ms，最多连续两次；之后恢复长间隔。开心表情本身闭眼，不叠加眨眼。
- 眨眼素材只有眼睛与附近毛发的透明补片，覆盖当前表情的眼睛，嘴巴和身体不变化。
- 首次待机约 0.8～1.6 秒开始动作，打开小窝时可提前到约 0.45 秒；完整动作约 0.5～1.36 秒，其他小动作约 2.1～3.2 秒，结束后再停留 2～5 秒。按宠物随机打乱完整动作列表，一轮中每种只出现一次，新一轮也避免首尾重复。
- 猫：摆尾、张望、伸懒腰、招手、动耳、蹭蹭、抖毛；柴犬：摆尾、招手、轻蹦、张望、动耳、伸懒腰、抖毛；兔子：动耳、张望、伸懒腰、招手、蹭蹭、轻蹦、抖毛；狐狸：动耳、张望、摆尾、招手、伸懒腰、蹭蹭、轻蹦。自然状态下会随动作短暂切换合适表情，再恢复自然。
- 小窝的“看看它的小动作”提供即时试玩。兔子用“蹭一蹭”替代“摇摇尾巴”，每款各 9 个按钮，包括“尝点心”“开心跳跳”；试玩同样遵循轻动效开关和系统减少动态效果。关闭轻动效后按钮禁用，系统减少动态效果时只显示静态表情并说明原因。试玩点心与玩耍也不增加互动记录。
- 倾诉、任务、等待、休息和主动互动期间暂停偶发动作。互动、点头和歪头使用起止归零的包络，脚部和画布边界固定，不积累漂移。

呼吸、耳尾、张望、侧蹭、抖毛仍使用原图的连续三角网格形变，眼睛、嘴巴与毛发一起移动。完整身体动作则直接裁取当前姿势，避免用拉伸一张坐姿原图来代替举爪、站高或腾空。完整动作资源失败时，仍可使用已有局部动作作为回退。

无需把毛绒耳朵和尾巴硬裁成独立贴片，也不会因转动图层露出空洞。采样保留相邻单元的余量，避免手机缩放下出现网格接缝；测试采样每个动作的完整周期，检查每个三角形保持正向、局部移动有界，防止放大动作后出现翻折。

## 完整身体动作

`public/pet-clips.js` 保存动作、姿势顺序和每段时长。四款各有招手、伸展、进食、跳跃四张独立的 `1536 × 1024` 透明 WebP；每张 6 列 × 4 行、每格 256px，全部 24 格按行继续同一个动作，不是四段重复的六帧动画。每段包含原有坐姿首尾和 22 张新绘中间姿势，合计 16 张图、384 个姿势。

招手用时 1000ms、伸展 1200ms、进食 1100ms，玩耍把完整跳跃播放两遍共 1600ms；轻蹦与庆祝只播放一次，用时 800ms。动作中的姿势按约 20～30fps 连续变化，每个姿势最多约 50ms，不再把伸展的一张图停留四百多毫秒。抬爪、身体舒展、送点心到嘴边，以及起跳前的蓄力和落地缓冲都有独立姿势。

招手会举起实际爪子；伸展会改变前肢、肩膀与躯干姿态；进食会捧起饼干、送到嘴边、咬下并收爪；玩耍包含蹲伏、推地、空中姿势与落地。动作本身包含对应面部表情，不把原坐姿的眨眼补片覆盖到已经移动的头上。动作期间暂停补片眨眼，回到原姿势后重新等待。

完整动作每次只绘制一个清晰、完整的身体姿势；招手以原坐姿的身体和脸部为固定底图，仅更新新绘前爪所在区域，减少毛发和脸形的逐帧闪动。在姿势上连续增加约 0.7 度以内的重心摆动、0.6% 以内的呼吸，以及伸展时约 1.8% 的舒展变化，绘制时以脚底为支点。首尾短暂过渡使用预乘透明度相加，避免身体突然变透明。动作时长与较长的互动说明分开，动作先自然完成，说明继续保留供阅读。连续点击仍会重新开始，普通刷新不会重播。

姿势变化的采样率与画布刷新率不同：新绘身体姿势约 20～30fps，连续重心、呼吸等变化的绘制目标为桌面 60fps、手机 30fps。补帧已经包含在本地图片中，运行时不生成图片、不计算光流，也不增加动画框架或模型依赖。

`scripts/build-pet-inbetweens.mjs` 在开发期整理 imagegen 的连续姿势图：按网格裁切、保留真实 alpha、清除边缘邻格的不相连碎片，用每个动作统一的比例和水平中心注册全部姿势。地面动作校准脚底，跳跃使用连续的抛物线式离地与落地位移。不会把每帧单独放大填满格子，否则伸展与跳跃会被缩放抵消。首尾沿用原有坐姿，脚本检查身体不贴输出边缘。

静止图与完整动作必须使用同一个显示标尺。原动作图为了容纳最宽的展开姿势，曾把兔子的普通坐姿也缩小到约 295px，而静止图为约 340px，切换时会明显小一圈。当前用 `scripts/build-pet-inbetweens.mjs --framing` 从原始 PNG 和四张动作图的首尾坐姿计算统一缩放、中心与脚底，输出 `public/pet-framing.js`。每个动作只使用一个校准变换，保留蹲伏、伸展与腾空的真实变化，不对每一帧分别填满画布。

静止与动作共用能容纳全部 96 个动作姿势的相机范围，并留出 16px 的保护空间。画布通过以脚底为基准的少量外扩补回静止形象的原显示大小，布局尺寸和回退 PNG 保持原有显示比例。这样不会通过缩小静止宠物来掩盖问题，也不会因把动作直接放大而裁掉耳朵。更换或重建动作图后应重新运行构图校准脚本。

```powershell
node scripts/build-pet-inbetweens.mjs <pet-id> <wave|stretch|feed|play> <6x4-sheet.png>
node scripts/build-pet-inbetweens.mjs --framing
node scripts/build-pet-inbetweens.mjs --preview
```

素材整理需要开发环境中的 `@napi-rs/canvas`，也可用 `CANVAS_MODULE_PATH` 指定已有模块；它不属于应用运行依赖。16 次内置 imagegen 调用的实际提示、源文件和输出路径见 [v4 提示记录](pet-action-prompts-v4.json)，动作中段见 [预览图](assets/pet-actions-v4.webp)。旧 v3 图和整理脚本继续保留，原来的版本化文件没有被覆盖。

## 素材、绘制与暂停

每款使用一个 `2688 × 384` WebP 条带：自然、温柔、开心、专注、困倦五个 384px 全身画面，之后是半闭与闭眼两个透明眼部帧。五个画面除面部补片外均来自相同的原图。四张条带合计 570,896 字节（约 558 KiB），每张小于 200 KB。生成和注册流程见 [素材记录](pet-assets.md) 与 [完整生成提示](pet-animation-prompts.md)。

只按需加载选中的宠物。动作按“宠物＋动作”分别缓存：自然待机可预取招手，伸展、进食、跳跃在实际需要时各加载一次；静止、倾诉、专注和休息不主动下载动作图。表情图、四种动作图各自独立，不会一次下载全部 16 张。用一个共享离屏画布完成当前宠物的表情合成、过渡或变形，再复制到可见的顶部头像、聊天卡片和小窝，避免每个位置重复计算。桌面目标上限约 60fps，700px 以下约 30fps；保留调度余量，避免刷新周期取整导致重复绘制或漏帧。显示画布 DPR 上限 2、边长上限 440px；表情原图为 384px，动作每格为 256px。

关闭“开启轻动效”或系统 `prefers-reduced-motion: reduce` 时，取消动画帧调度，只在状态／布局变化时绘制静态表情。页面隐藏和所有形象离开视野时停止连续绘制；不可见期间不推进动画时钟，回来后重置眨眼和小动作的等待时间，不追赶积压帧。已经过期的互动反馈不会在回到页面时重新播放。原有 CSS 星光只响应主动互动，同样遵循动效开关和系统偏好。

表情图先等待 `Image.decode()`；完整动作图通过 `createImageBitmap(Blob)` 异步解码成可复用位图，再裁取当前姿势绘制，避免首次 `drawImage()` 才处理整张 WebP。动作缓存最多保留最近使用的八张图，解码像素约 48MiB；淘汰时释放位图并取消未完成的请求，播放器销毁时释放全部图。被淘汰的动作可通过版本化 HTTP 缓存重新读取。不支持 ImageBitmap 时沿用 Image 解码路径，加载或解码失败仍使用原有回退方式。动画只在实际需要绘制的刷新回调里查询可见布局，避免高刷新率屏幕上跳过绘制时仍反复触发布局计算。

普通数据同步和摸摸、喂食、玩耍只更新小窝中的名字、点数、说明和按钮状态，保留正在运行的画布、名字输入框与聊天输入区。切换宠物时才重建小窝内容；异步操作完成后恢复原控件的键盘焦点，用户已关闭小窝或移动焦点时不抢回焦点。宠物联动开关在设置页保存后立即更新当前表现。

新节点由 `MutationObserver` 接入，共享当前状态；删除的节点会解除 `IntersectionObserver` 订阅。完整动作图缺失或尺寸不符时保留五种表情与原有局部动作；表情资源缺失、尺寸不符或画布不可用时保留原始 PNG；原图也失败时使用原有替代提示。资源采用显式静态路径白名单、正确 WebP MIME 与版本化长期缓存，不能请求任意路径。

## 验证范围

`tests/pet-motion.test.mjs` 检查需要／互动／音乐优先级、单次和双次眨眼、动作轮换与暂停、可见幅度、预备／离地／落地阶段、完整周期网格稳定性、素材大小及 HTTP 缓存。`tests/pet-clips.test.mjs` 额外检查完整动作有限播放、24 个姿势都被访问、单跳与双跳、每个姿势最多 50ms、alpha、图幅和静态服务白名单。`tests/pet-motion-browser.spec.mjs` 在离线 Chrome 中检查实际画布内容、四款各四种完整动作、逐帧顺序、眨眼不错误叠加、按动作缓存、动效开关、系统偏好、隐藏／离屏暂停、素材缺失与尺寸错误回退、试玩零请求／零加分、真实聊天恢复，以及 320／390px 手机布局。使用受控时钟验证等待时间，不依赖真实模型或音乐服务；真实音乐播放还由原有宠物与媒体浏览器测试覆盖。

`tests/pet-cadence-browser.spec.mjs` 检查伸展中段持续进入新姿势、四款轮廓保持清楚、减少动态效果后停止，以及没有额外的运行时插帧资源。`tests/pet-density-browser.spec.mjs` 比较新旧动作的相邻画面变化幅度，检查每段确有不同中间姿势，并验证晚到的招手预加载不会重置正在播放的其他动作。`node scripts/profile-pet-motion.mjs` 可在不改动用户数据的临时服务中采样桌面与 4 倍 CPU 限速的手机视口；采样只代表本机环境，不保证所有手机的实际帧率。

`tests/pet-framing-browser.spec.mjs` 对四款宠物的四种动作测量实际 CSS 像素尺寸，比较普通坐姿进入／退出动作时的宽高和脚底。静止画布也单独与原 PNG 的真实显示尺寸比较，避免通过一起缩小两套素材来让检查通过；另检查抬爪、展开耳朵和跳跃全周期没有贴到画布边缘。

`tests/pet-regressions-browser.spec.mjs` 覆盖回复到达和宠物版本变化期间的名字输入、中文输入节点与光标保留、键盘互动与失败重试、取名后图片的无障碍名称、动作图异步解码等待与失败回退、三种园林主题的标题对比度，以及桌面／手机设置页上宠物联动开关的即时生效。
